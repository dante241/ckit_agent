# Config Globals & File-Based Config

> Layer 3: File-based configuration and runtime globals

## CustomConfigUtils

**Location**: `include/utils/CustomConfigUtils.php`

Persists runtime overrides of `config_override.php` values into a SEPARATE file, `$customConfigFile = 'config_override.cus.php'` (set at the end of `config_override.php`). Never write `config_override.php` from code.

### saveCustomConfigs(array $configs)

Real signature: `static function saveCustomConfigs(array $configs)` — no return value. It includes the current `config_override.cus.php` (a `return [...]` array), sets each key **flat** (`$customConfigs['callCenterConfig.enable'] = true`, the dot path is kept as the key), then rewrites the file via `FileUtils::writeReturnArrayToFile(..., 'WARNING: DO NOT MODIFY THIS FILE!!!')`.

**Example** (real caller `modules/Settings/Vtiger/actions/SaveCallCenterConfig.php`):
```php
CustomConfigUtils::saveCustomConfigs([
	'callCenterConfig.enable' => $enable,
]);
```

**Generated File** (`config_override.cus.php` — auto-generated, do not hand-edit):
```php
<?php

/*
	System auto-generated on ... WARNING: DO NOT MODIFY THIS FILE!!!
*/

return array(
    'currentVersion' => '7.1.0.20220711.1800',
    'callCenterConfig.enable' => true,
);
```

### loadCustomConfigs()

Called by `config_override.php` as its LAST statement. For each dot-path key it sets the value on the top-level global (`Arr::set` on `$GLOBALS[<first segment>]`), so `'callCenterConfig.enable' => true` overrides only `$callCenterConfig['enable']` and keeps the other defaults.

**Access Pattern**:
```php
// After boot, access via global
global $callCenterConfig;

if (!empty($callCenterConfig['enable'])) {
	$provider = $callCenterConfig['provider'];
}
```

## Core Config Files

### config.inc.php

Core system configuration (DB connection, `$site_URL`, `$root_directory`, upload limits) — generated by installer; don't add feature config here.

### config_override.php

Tracked in git: defaults for every feature config (`$callCenterConfig = [...]`, `$validationConfig = [...]`, …). Add NEW default config here in code changes, ABOVE the line `// Load custom config. ALL CONFIG MUST BE BEFORE THIS LINE!!!`. Runtime changes from Settings pages go to `config_override.cus.php` via `saveCustomConfigs()`, not here.

## Global Access Patterns

### vglobal() Function

Real signature (`includes/runtime/Globals.php`): `function vglobal($key, $value=null)` — getter AND setter. With `$value !== null` it assigns `$GLOBALS[$key]`; it returns `$GLOBALS[$key]` or **`false`** when unset (not `null`).

```php
$siteUrl = vglobal('site_URL');
vglobal('default_charset', 'UTF-8');      // setter
```

### $GLOBALS Array

Direct access to runtime config.

```php
// Read config
global $callCenterConfig;
if (!empty($callCenterConfig['enable'])) {
    // Feature enabled
}

// Or use $GLOBALS directly
if (!empty($GLOBALS['callCenterConfig']['enable'])) {
    // Feature enabled
}
```

### global Keyword

Declare specific globals in function scope.

```php
function checkFeatureEnabled(): bool {
    global $callCenterConfig;

    return !empty($callCenterConfig['enable']);
}
```

## Common Config Access Patterns

### Feature Toggle Check

```php
class PBXManager_Config_Helper {
    public static function isCallCenterEnabled(): bool {
        global $callCenterConfig;

        if (empty($callCenterConfig['enable'])) {
            return false;
        }

        return true;
    }
}
```

### Get Config Value with Default

```php
global $callCenterConfig;
$provider = $callCenterConfig['provider'] ?? 'default';
$apiUrl = $callCenterConfig['api_url'] ?? 'https://api.default.com';
```

### Conditional Config Loading

```php
global $callCenterConfig;

if (!empty($callCenterConfig['enable'])) {
    $dbConfig = Settings_Vtiger_Config_Model::loadConfig('callcenter_config', true);
    // Use DB config for detailed settings
}
```

## When to Use Each Config Type

| Config Type | Use When |
|---|---|
| **File Config** (`$GLOBALS`) | Static server settings, feature flags, rarely changed values |
| **DB System Config** | Dynamic module settings, API keys, thresholds, frequently changed |
| **User Preferences** | User-specific UI settings, per-user behavior, notifications |

**Example Workflow**:
1. **File Config**: Enable/disable call center feature globally
2. **DB System Config**: Store provider API credentials, sync settings
3. **User Preferences**: Each user's auto-answer preference, ringtone choice
